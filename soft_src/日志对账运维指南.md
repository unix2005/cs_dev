# 日志对账运维指南（netd / bizd / login / knockd）

## 1. 统一对账键格式

各服务日志使用同一标识串，便于跨服务 grep 关联同一次客户端请求：

```
src_ip#id[(uid=<64hex>)]
```

- `src_ip`：客户端**真实**源 IP（IPv4 点分 / IPv6 冒分）。netd 经 `accept/recvfrom` 取得；
  bizd / login 经 IPC / JSON 透传，与 netd 保持一致。
- `id`：请求号。由 **netd 每帧生成**（`netd_cid`），经 IPC `Q_IPC_T_REQID` TLV 透传到 bizd，
  bizd 原样作为 JSON `"id"` 下发给微服务（login 即读取此值）。
  故 `src_ip#id` 在 netd / bizd / login 三处**完全一致**。
- `uid`：登录后用户标识（32 字节 SM3 的 hex）。仅已登录（user_id 非全 0）时出现；
  匿名请求不附加，避免污染日志。

> knockd 是“开门”网关，不向 netd/bizd 透传请求号，其 `id` 为本进程**本地序号**；
> 跨服务关联 knockd 与其余三者时，请以**真实 `src_ip`** 作为关联键（同一客户端 IP 在四服务日志中一致）。

## 2. 各服务典型日志行

### netd（客户端入站侧）
```
[recv] 203.0.113.7#99 cmd=1 <-- 客户端
转发登录请求 203.0.113.7#99(uid=e3b0…855) -> bizd
登录请求已转发 203.0.113.7#99(uid=e3b0…855) result=0
[send] 203.0.113.7#99 cmd=1 --> 客户端 outlen=...
```
IPv6 示例：`2001:db8::1#12(uid=…)`。

### bizd（业务分发侧）
```
请求解析失败 203.0.113.7#99(uid=e3b0…855)
请求处理完成 203.0.113.7#99(uid=e3b0…855) cmd=...
请求分发失败 203.0.113.7#99(uid=e3b0…855)
```
bizd 的 `src_ip#id` 与 netd 完全相同（来自同一 IPC 透传）。

### login（微服务侧）
```
[recv] 203.0.113.7#99(uid=e3b0…855) <-- 127.0.0.1
[send] 203.0.113.7#99(uid=e3b0…855) ... --> 127.0.0.1 (user=qiaoshui, tok=900787de87fd002c)
```

### knockd（SPA 单包授权网关）
```
SPA 校验失败 cid=203.0.113.7#5 len=...
SPA 授权成功 203.0.113.7#5(uid=…) ttl=300
```
`cid` 格式即 `src_ip#seq[(uid=...)]`，与上面三服务同源。

## 3. 常用 grep 关联

### 3.1 按请求号串联一次完整请求（netd→bizd→login）
```bash
grep '203.0.113.7#99' /var/log/netd.log /var/log/bizd.log /var/log/login.log
```
IPv6 客户端（注意 IPv6 地址含 `:` 需用单引号或转义）：
```bash
grep '2001:db8::1#12' /var/log/netd.log /var/log/bizd.log /var/log/login.log
```

### 3.2 按客户端 IP 拉取该 IP 的全部活动（含 knockd 开门记录）
```bash
grep -E '203\.0\.113\.7' /var/log/netd.log /var/log/bizd.log /var/log/login.log /var/log/knockd.log
```
`grep -E` 时用 `\.` 锚定 IPv4 段，避免误命中其它数字；IPv6 直接用字面量即可。

### 3.3 按登录用户 uid 关联其所有请求
```bash
grep 'uid=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855' \
     /var/log/netd.log /var/log/bizd.log /var/log/login.log
```

### 3.4 只看失败/异常
```bash
grep -E '请求解析失败|请求分发失败|转发.*失败|SPA 校验失败' \
     /var/log/netd.log /var/log/bizd.log /var/log/knockd.log
```

## 4. 注意事项
- **IPv6 全程贯通**：netd 的 `SRC_IP` IPC TLV 与 bizd 的 token 绑定地址均已扩为 `[1B 族][16B 地址]`，
  故 IPv6 客户端现在能在四服务日志用同一 `2001:db8::1#id` 关联，不再退化成 `0.0.0.0`。
- **token 绑定**：netd 签发会话 Token 时绑定的是**真实源地址**（v4/v6 统一），
  校验失败会因源地址不符被拒（见 `q_chan_token_validate`）。
- **旧版兼容**：bizd 解析 `SRC_IP` TLV 时，17 字节新格式与 4 字节旧格式（仅 IPv4）均可识别；
  老 netd 发来的 4 字节 TLV 仍按 IPv4 正确解析。
